## Executive Summary

This study documents the scoring algorithms for [INS-001.2 Common Ground](https://instruments.phronos.org/ins-001/ins-001-2/) semantic bridging (also called "Common Ground") assessment. The framework measures two orthogonal properties of word associations:

1. **Spread** — semantic territory covered by clues (primary divergence metric)
2. **Fidelity** — how well clues jointly identify the bridging task (task validity metric)

### Key Finding: Metric Independence

The original relevance metric (min cosine similarity to endpoints) was highly correlated with spread (r = -0.61), providing redundant information. The new fidelity metric achieves independence:

| Metric Pair | Correlation | Interpretation |
|-------------|-------------|----------------|
| Spread × Old Relevance | r = -0.61 | Redundant (tradeoff) |
| Spread × Fidelity | r = +0.055 | **Independent** |

This enables a genuine 2×2 interpretation space:

|  | Low Fidelity | High Fidelity |
|--|--------------|---------------|
| **High Spread** | Scattered/random | Creative & precise |
| **Low Spread** | Off-task & clustered | Conventional but accurate |

### Haiku Baselines

| Metric | Haiku Mean | Haiku SD | Scale |
|--------|------------|----------|-------|
| Spread | 64.4 | 4.6 | 0–100 |
| Fidelity | 0.68 | 0.13 | 0–1 |

## 1. Metric Overview

### 1.1 Metric Roles

| Metric | Role | Range | Independence |
|--------|------|-------|--------------|
| **Spread** | Divergence within constraint | 0–100 | — |
| **Fidelity** | Task validity / triangulation quality | 0–1 | r = 0.055 with spread |

### 1.2 Why Two Metrics?

The bridging task has two failure modes:

1. **Low spread, any fidelity**: Clues cluster together—limited exploration of semantic space
2. **Any spread, low fidelity**: Clues don't jointly identify the pair—off-task or random

A single metric cannot capture both. Spread measures divergent thinking; fidelity measures task engagement. Their independence means a participant can excel at one without the other.

### 1.3 Literature Basis

**Spread**: Adapts the Divergent Association Task (DAT) methodology from [Olson et al. (2021)](https://www.pnas.org/doi/10.1073/pnas.2022340118), which validated mean pairwise semantic distance as a creativity measure. The bridging constraint compresses achievable spread by ~8 points relative to unconstrained DAT.

**Fidelity**: Novel metric developed for INS-001.2. Based on information-theoretic intuition: good clues should collectively narrow down the solution space through complementary (non-redundant) constraint.

## 2. Spread (Constrained Divergence)

Spread measures how much semantic territory a submission covers. This is the primary divergence metric.

### 2.1 Calculation

Mean pairwise cosine distance among clues only, scaled to 0–100:

$$
\text{spread} = 100 \times \frac{1}{\binom{n}{2}} \sum_{i < j} \left(1 - \cos(\mathbf{c}_i, \mathbf{c}_j)\right)
$$

Where:
- $n$ = number of clues
- $\mathbf{c}_i$ = embedding for clue $i$

**Why clue-only?** Including anchor-target in the calculation conflates pair difficulty with participant performance. Clue-only spread isolates the participant's contribution.

### 2.2 Relationship to DAT

While spread uses the same formula as DAT, the constructs differ:

| Property | DAT | INS-001.2 Spread |
|----------|-----|------------------|
| Task goal | Generate maximally distant words | Bridge anchor-target |
| Constraint | None | Must maintain fidelity to both endpoints |
| Typical score | 78 (human mean) | 66 (Haiku mean) |

The ~12-point gap reflects the geometric cost of the bridging constraint.

### 2.3 Clue Count Considerations

Spread stabilizes after 3–4 clues:

| Clues | Pairs | Mean Spread | SD |
|-------|-------|-------------|-----|
| 2 | 1 | 61.6 | 5.1 |
| 3 | 3 | 63.3 | 4.8 |
| 4 | 6 | 64.1 | 4.7 |
| 5 | 10 | 64.4 | 4.6 |

Recommended configuration: **4–5 clues**.

## 3. Fidelity (Joint Constraint)

Fidelity measures how well clues collectively identify the anchor-target pair by eliminating plausible alternatives.

### 3.1 Intuition

Good bridging clues should:
- **Coverage**: Eliminate most alternative endpoints (each clue rules out some wrong answers)
- **Efficiency**: Be non-redundant (different clues eliminate different wrong answers)

Bad clues either:
- Eliminate nothing (uninformative—too far from endpoints)
- All eliminate the same foils (redundant—no complementary information)

### 3.2 Algorithm

```python
def calculate_fidelity(
    clue_embeddings: list[list[float]],
    anchor_embedding: list[float],
    target_embedding: list[float],
    foil_anchors: list[list[float]],  # 50 nearest neighbors of anchor
    foil_targets: list[list[float]],  # 50 nearest neighbors of target
) -> dict:
    """
    Measure how well clues jointly constrain the solution space.
    
    A foil is "eliminated" by a clue if that clue is more similar to the
    true endpoint than to the foil.
    """
    
    def get_eliminations(clue_emb, true_emb, foil_embs):
        """Return set of foil indices eliminated by this clue."""
        true_sim = cosine_similarity(clue_emb, true_emb)
        eliminated = set()
        for i, foil in enumerate(foil_embs):
            foil_sim = cosine_similarity(clue_emb, foil)
            if true_sim > foil_sim:
                eliminated.add(i)
        return eliminated
    
    # Compute eliminations for each clue
    anchor_elims = [get_eliminations(c, anchor_embedding, foil_anchors) 
                    for c in clue_embeddings]
    target_elims = [get_eliminations(c, target_embedding, foil_targets) 
                    for c in clue_embeddings]
    
    # Coverage: fraction of foils eliminated by at least one clue
    anchor_union = set.union(*anchor_elims) if anchor_elims else set()
    target_union = set.union(*target_elims) if target_elims else set()
    anchor_coverage = len(anchor_union) / len(foil_anchors)
    target_coverage = len(target_union) / len(foil_targets)
    
    # Efficiency: 1 - (intersection / union)
    def compute_efficiency(elim_sets):
        if len(elim_sets) < 2:
            return 1.0
        union = set.union(*elim_sets)
        if not union:
            return 0.0
        intersection = set.intersection(*elim_sets)
        redundancy = len(intersection) / len(union)
        return 1 - redundancy
    
    anchor_efficiency = compute_efficiency(anchor_elims)
    target_efficiency = compute_efficiency(target_elims)
    
    # Combined metrics
    overall_coverage = (anchor_coverage + target_coverage) / 2
    overall_efficiency = (anchor_efficiency + target_efficiency) / 2
    fidelity = overall_coverage * overall_efficiency
    
    return {
        "fidelity": fidelity,
        "coverage": overall_coverage,
        "efficiency": overall_efficiency
    }
```

### 3.3 Foil Generation

Foils are the 50 nearest neighbors of each endpoint in embedding space:

```python
def generate_endpoint_foils(
    endpoint_embedding: list[float],
    vocabulary_embeddings: dict[str, list[float]],
    n_foils: int = 50
) -> list[list[float]]:
    """
    Generate hard-to-distinguish foils using nearest neighbors.
    """
    vocab_embs = list(vocabulary_embeddings.values())
    similarities = [cosine_similarity(endpoint_embedding, v) for v in vocab_embs]
    sorted_indices = np.argsort(similarities)[::-1]
    # Skip index 0 (might be the word itself)
    foil_indices = sorted_indices[1:n_foils+1]
    return [vocab_embs[i] for i in foil_indices]
```

**Why nearest neighbors?** These are the hardest foils to distinguish—words semantically similar to the true endpoint. If clues can eliminate these, they carry strong signal about the true pair.

### 3.4 Component Interpretation

Fidelity decomposes into coverage × efficiency:

| Component | Meaning | Low Value | High Value |
|-----------|---------|-----------|------------|
| Coverage | Fraction of foils eliminated | Clues too distant from endpoints | Clues in right neighborhood |
| Efficiency | Non-redundancy of elimination | All clues eliminate same foils | Complementary information |

Both components contribute to fidelity. A score can be high-coverage but low-efficiency (redundant conventional clues) or low-coverage but high-efficiency (sparse but complementary).

## 4. Fidelity Calibration Study

### 4.1 Problem Statement

The original INS-001.2 relevance metric used min(sim_anchor, sim_target) per clue. Calibration revealed this was highly correlated with spread:

| Correlation | Value | Implication |
|-------------|-------|-------------|
| Spread × Relevance | r = -0.61 | Redundant metrics |
| Relevance × A-T Distance | r = -0.41 | Confounded by difficulty |

This tradeoff is geometric: clues close to both endpoints (high relevance) must cluster together (low spread).

### 4.2 Alternative Metrics Evaluated

Three approaches were tested for independence from spread:

| Approach | Metric | Spread Correlation | Passed? |
|----------|--------|-------------------|---------|
| **Discriminative** | Percentile rank vs. foil pairs | r = -0.11 | ✓ |
| **Joint Constraint** | Coverage × Efficiency | r = +0.06 | ✓ |
| **Balance** | Anchor-target attention balance | r = -0.16 | ✓ |

All three achieved the target of |r| < 0.30.

### 4.3 Metric Selection: Joint Constraint

Joint constraint (fidelity) was selected based on:

| Criterion | Discriminative | Joint Constraint | Balance |
|-----------|----------------|------------------|---------|
| Spread correlation | -0.11 | **+0.06** | -0.16 |
| A-T distance correlation | -0.25 | **+0.02** | -0.05 |
| Distribution variance | SD=0.20 | **SD=0.13** | SD=0.05 |
| Ceiling effect | 61% at 1.0 | 15% max bin | 22% max bin |

Joint constraint had:
- Lowest correlation with spread (most independent)
- Lowest correlation with A-T distance (least confounded by difficulty)
- No ceiling effect (meaningful variance across full range)
- Interpretable decomposition (coverage + efficiency)

*Figure 1: Independence from spread. All three metrics pass the r < 0.30 criterion. Joint constraint (middle) shows the flattest relationship.*

## 6. Legacy Relevance Metric

The original relevance metric is retained for backwards compatibility and internal analysis.

### 6.1 Calculation

$$
\text{relevance} = \frac{1}{n} \sum_{i=1}^{n} \min\left(\cos(\mathbf{c}_i, \mathbf{a}), \cos(\mathbf{c}_i, \mathbf{t})\right)
$$

### 6.2 Usage

| Context | Use Relevance? | Use Fidelity? |
|---------|----------------|---------------|
| User-facing results | No | Yes |
| Validity gate (< 0.15 = invalid) | Yes | No |
| Internal analysis | Optional | Yes |
| Backwards compatibility | Yes | — |

### 6.3 Why Fidelity Replaced Relevance

| Issue | Relevance | Fidelity |
|-------|-----------|----------|
| Spread correlation | r = -0.61 (redundant) | r = +0.06 (independent) |
| A-T distance correlation | r = -0.41 (confounded) | r = +0.02 (unconfounded) |
| Interpretation | "How close to corridor" | "How well do clues triangulate" |
| Failure detection | Only catches distant clues | Catches redundant and uninformative clues |

## 7. Implementation

### 7.1 Core Functions

| Function | Purpose |
|----------|---------|
| `cosine_similarity()` | Fundamental similarity calculation |
| `calculate_spread()` | Mean pairwise distance among clues |
| `calculate_fidelity()` | Joint constraint score |
| `generate_endpoint_foils()` | Nearest-neighbor foil generation |
| `score_union()` | Complete INS-001.2 scoring |

### 7.2 Return Schema

`score_union()` returns:

```python
{
    "spread": float,              # Clue-only divergence (0-100)
    "fidelity": float,            # Joint constraint score (0-1)
    "fidelity_coverage": float,   # Coverage component (0-1)
    "fidelity_efficiency": float, # Efficiency component (0-1)
    "relevance": float,           # Legacy metric (0-1)
    "valid": bool                 # Whether relevance >= 0.15
}
```

### 7.3 Dependencies

- **Embedding model**: OpenAI text-embedding-3-small (1536 dimensions)
- **Vocabulary**: ~5000 common English nouns for foil generation
- **Calibration reference**: Claude Haiku 4.5 (claude-haiku-4-5-20251001)

### 7.4 Computational Cost

| Operation | Calls | Notes |
|-----------|-------|-------|
| Clue embeddings | n | Already computed for spread |
| Foil generation | 2 | Once per endpoint, cacheable |
| Elimination computation | n × 100 | n clues × 100 foils |

Total: O(n) additional embedding lookups beyond spread calculation.

## 8. Limitations

| Limitation | Impact | Mitigation |
|------------|--------|------------|
| **Foil quality** | Nearest neighbors may not be optimal foils | Use sufficiently large vocabulary; consider frequency weighting |
| **Vocabulary dependence** | Different vocabularies yield different foils | Standardize vocabulary; document in methods |
| **Embedding model dependence** | Different models yield different scores | Standardize on single model; re-calibrate if changed |
| **Haiku baseline stability** | AI capabilities may shift | Lock model version; re-calibrate periodically |
| **No human validation yet** | Fidelity validated against Haiku, not human creativity measures | Plan human validation study |
