## Executive Summary

This study documents the scoring algorithms underlying INS-001 Semantic Cartography instruments. The framework measures two properties of word associations:

1. **Relevance** — validity filter ensuring clues connect to the prompt (gate function)
2. **Spread** — constrained divergence measuring semantic territory covered (primary metric)

Key findings from calibration study:

- **Spread is not equivalent to DAT divergence**: The bridging task's relevance constraint compresses achievable spread by ~8 points relative to unconstrained DAT scores
- **Relevance-spread tradeoff**: Strong inverse correlation (r = -0.61) means these metrics are not independent; relevance serves as validity filter, not a separate score
- **Haiku baseline**: Claude Haiku 4.5 establishes reference distributions for "optimal bridging" against which human performance can be compared
- **Pair difficulty moderation**: Harder anchor-target pairs reduce both achievable relevance (r = -0.41) and spread

**Terminology note**: In the INS-001.2 user interface, "spread" refers to what this document calls constrained divergence. The term "spread" is preferred for user-facing contexts as it avoids confusion with the distinct DAT construct.

## 1. Metric Overview

### 1.1 Metric Roles

The two metrics serve distinct functions:

| Metric | Role | Range | UI Label |
|--------|------|-------|----------|
| **Relevance** | Validity filter (gate) | 0–1 | — (not displayed) |
| **Spread** | Primary performance metric | 0–100 | "Spread" |

### 1.2 Relationship Between Metrics

Unlike the original design assumption of orthogonality, calibration revealed a strong inverse relationship:

| Level | Correlation | Interpretation |
|-------|-------------|----------------|
| Trial-level | r = -0.61 | Higher relevance → Lower spread |
| Clue-level | r = -0.74 | More relevant clues cluster together |

This tradeoff is geometric: clues that bridge both endpoints well must lie in the intersection of two semantic neighborhoods, limiting how far apart they can spread.

**Implication**: Relevance is used as a validity gate (≥ 0.15), not as a separate interpretable score. Spread is the primary metric reported to users.

![Relevance-Spread Tradeoff](/images/methods/semantic-association-metrics/relevance-divergence-scoring/relevance_divergence_tradeoff.png)
*Figure 1: Trial-level (left) and clue-level (right) tradeoff between relevance and spread. Color indicates anchor-target distance.*

### 1.3 Literature Basis

**Spread**: Adapts the Divergent Association Task (DAT) methodology from [Olson et al. (2021)](https://phronos.org/library/digital-validity/#dat-methodology), which validated mean pairwise semantic distance as a creativity measure (r ≈ 0.40 with composite creativity scores). However, INS-001.2's bridging constraint fundamentally alters the construct (see [Section 4](#4-calibration-study)).

**Relevance**: Standard information retrieval approach using distributional semantics. For INS-001.2, relevance uses minimum similarity to both endpoints, ensuring genuine bridging rather than clustering near one concept.

## 2. Relevance

Relevance measures whether a participant's clues actually connect to the prompt. It serves as a **validity filter**, not a performance metric.

### 2.1 INS-001.1 (Radiation): Similarity to Seed

For single-seed tasks, relevance is the mean cosine similarity between each clue and the seed:

$$
\text{relevance}_{\text{radiation}} = \frac{1}{n} \sum_{i=1}^{n} \cos(\mathbf{c}_i, \mathbf{s})
$$

Where:
- $\mathbf{c}_i$ = embedding vector for clue $i$
- $\mathbf{s}$ = embedding vector for seed
- $n$ = number of clues

### 2.2 INS-001.2 (Union): Minimum Similarity to Both Endpoints

For anchor-target tasks, relevance uses the minimum similarity to ensure clues bridge both concepts:

$$
\text{relevance}_{\text{union}} = \frac{1}{n} \sum_{i=1}^{n} \min\left(\cos(\mathbf{c}_i, \mathbf{a}), \cos(\mathbf{c}_i, \mathbf{t})\right)
$$

Where:
- $\mathbf{a}$ = embedding vector for anchor
- $\mathbf{t}$ = embedding vector for target

**Rationale for min()**: Using minimum rather than mean penalizes clues that cluster near one endpoint. A clue with similarity 0.8 to anchor but 0.1 to target receives relevance 0.1, correctly identifying it as failing to bridge.

### 2.3 Relevance as Validity Gate

Calibration against Haiku established that relevance functions best as a binary validity filter:

| Relevance | Interpretation | Action |
|-----------|----------------|--------|
| < 0.15 | Invalid | Flag submission; do not interpret spread |
| ≥ 0.15 | Valid | Report spread as primary metric |

**Why 0.15?** Haiku's minimum observed relevance across 114 trials was 0.157. The 0.15 threshold catches submissions that fail to engage with the task (random words, gibberish) while accepting all legitimate bridging attempts.

### 2.4 Pair Difficulty Effect on Relevance

Harder pairs (more distant anchor-target) constrain achievable relevance:

| Pair Difficulty | A-T Distance | Mean Relevance |
|-----------------|--------------|----------------|
| Easy | < 0.73 | 0.290 |
| Medium | 0.73–0.78 | 0.292 |
| Hard | > 0.78 | 0.245 |

Correlation: r = -0.41 (p < 0.001)

![Pair Difficulty vs Relevance](/images/methods/semantic-association-metrics/relevance-divergence-scoring/relevance_characterization.png)
*Figure 2: Harder pairs (more distant anchor-target) reduce achievable relevance. The "bridging region" shrinks as endpoints diverge. (Bottom-left panel)*

## 3. Spread (Constrained Divergence)

Spread measures how much semantic territory a submission covers, subject to the relevance constraint. This is the primary performance metric.

### 3.1 Calculation: Clue-Only Pairwise Distance

Spread is computed as mean pairwise cosine distance between clues only, scaled to 0-100:

$$
\text{spread} = 100 \times \frac{1}{\binom{n}{2}} \sum_{i < j} \left(1 - \cos(\mathbf{c}_i, \mathbf{c}_j)\right)
$$

Where:
- $n$ = number of clues
- $\mathbf{c}_i$ = embedding for clue $i$

**Why clue-only?** Including anchor-target in the calculation (as in earlier versions) conflates pair difficulty with participant performance. Clue-only spread isolates the participant's contribution and is more directly comparable to DAT.

### 3.2 Relationship to DAT

While spread uses the same mathematical formula as DAT (mean pairwise cosine distance × 100), the constructs differ:

| Property | DAT | INS-001.2 Spread |
|----------|-----|------------------|
| Task goal | Generate maximally distant words | Generate words bridging anchor-target |
| Constraint | None (unconstrained divergence) | Must maintain relevance to both endpoints |
| Word source | All participant-generated | All participant-generated |
| Typical score | 78 (human mean) | 66 (Haiku mean) |

The ~8-point gap reflects the geometric cost of the relevance constraint.

### 3.3 Clue Count Considerations

Spread scores stabilize after 3-4 clues:

| Clues | Pairs | Mean Spread | SD |
|-------|-------|-------------|-----|
| 2 | 1 | 61.6 | 5.1 |
| 3 | 3 | 63.3 | 4.8 |
| 4 | 6 | 64.1 | 4.7 |
| 5 | 10 | 64.4 | 4.6 |

Marginal contribution becomes non-significant after clue 2. The recommended configuration is **4-5 clues**, balancing measurement stability with task burden.

**Implementation note**: Based on this analysis, the INS-001.2 UI allows participants to submit up to 5 clues. This provides 10 clue-clue pairs for spread calculation while maintaining reasonable task length. Participants may submit fewer clues (minimum 2), though spread estimates become less stable with fewer pairs.

## 4. DAT Calibration Study

### 4.1 Study Design

To establish the relationship between INS-001.2 spread and DAT divergence, we ran Claude Haiku 4.5 through both tasks:

**DAT Protocol** (Olson et al. 2021):
- Prompt: "Generate 10 nouns as different from each other as possible"
- Scoring: First 7 valid nouns, 21 pairwise distances, mean × 100
- Trials: 150 at temperature 0.7

**INS-001.2 Protocol**:
- Task: Generate 5 clues bridging anchor-target pairs
- Scoring: Clue-only pairwise distance (10 pairs), mean × 100
- Trials: 114 at temperature 0.7

### 4.2 Key Results

**Haiku reference scores:**

| Task | Mean | SD | Range |
|------|------|-----|-------|
| DAT (7 words, 21 pairs) | 74.10 | 1.57 | 70.9–79.0 |
| INS-001.2 spread (5 clues, 10 pairs) | 64.44 | 4.57 | — |
| INS-001.2 full divergence (7 words, 21 pairs) | 66.20 | 4.70 | — |

**Calibration gap**: +8.3 points (INS-001.2 → DAT equivalent)

![Haiku Score Distributions](/images/methods/semantic-association-metrics/relevance-divergence-scoring/dat_calibration_results.png)
*Figure 4: Distribution of Haiku scores on DAT vs INS-001.2. The ~8-point gap reflects the relevance constraint's geometric cost. (Left panel)*

### 4.3 Construct Validity Assessment

The calibration gap is not measurement error—it reflects a fundamental construct difference:

**Pairwise distance comparison:**
- DAT word pairs: mean distance = 0.741
- INS-001.2 clue pairs: mean distance = 0.637
- Difference: t = 38.0, p < 0.001, Cohen's d = 1.20

The relevance constraint compresses clue-clue distances by requiring all clues to remain in the intersection of anchor and target neighborhoods.

![Pairwise Distance Distributions](/images/methods/semantic-association-metrics/relevance-divergence-scoring/dat_calibration_results.png)
*Figure 5: Distribution of pairwise distances. DAT pairs (blue) spread further than bridging clue pairs (orange). (Middle panel)*

### 4.4 Pair Difficulty Moderation

Anchor-target distance moderates achievable spread:

| Pair Difficulty | A-T Distance | Clue-Clue Spread |
|-----------------|--------------|------------------|
| Easy | < 0.73 | 63.75 |
| Medium | 0.73–0.78 | 64.84 |
| Hard | > 0.78 | 67.55 |

Correlation: r = 0.23 (p = 0.015), ANOVA F = 8.08 (p < 0.001)

Counter-intuitively, harder pairs allow *more* spread—distant endpoints create a larger (though sparser) bridging region.

![Pair Difficulty Moderation](/images/methods/semantic-association-metrics/relevance-divergence-scoring/pair_difficulty_moderation.png)
*Figure 6: Clue-clue spread by pair difficulty tercile. Harder pairs allow more spread.*

### 4.5 Calibration Recommendations

**Do not report "DAT-equivalent" scores.** The constructs are sufficiently different that a linear adjustment (+8.3 points) would be misleading. Instead:

1. **Report raw spread** on 0-100 scale with INS-001.2-specific interpretation bands
2. **Compare to Haiku baseline** on the same pair (percentile or delta)
3. **Acknowledge constraint** in methods: "Spread measures divergence under a bridging relevance constraint"

## 5. Interpretation Thresholds

### 5.1 Relevance Threshold

Relevance serves as a binary validity gate:

| Score | Interpretation | Action |
|-------|----------------|--------|
| < 0.15 | Invalid | Do not interpret spread; flag for review |
| ≥ 0.15 | Valid | Proceed with spread interpretation |

This threshold is calibrated to catch non-engagement (random words, gibberish) while accepting all legitimate bridging attempts. Haiku's minimum observed relevance was 0.157.

### 5.2 Spread Thresholds (Haiku-Calibrated)

Interpretation bands based on Haiku reference distribution (5 clues):

| Score | Label | Description | Haiku Percentile |
|-------|-------|-------------|------------------|
| < 55 | Low | Very constrained associations | < 5th |
| 55–62 | Below Average | Limited exploration | 5th–25th |
| 62–68 | Average | Typical bridging performance | 25th–75th |
| 68–72 | Above Average | Wide-ranging associations | 75th–95th |
| > 72 | High | Exceptional spread | > 95th |

**Note**: These thresholds differ from DAT norms (where 78 is average). Direct comparison to DAT scores is not appropriate.

### 5.3 Pair-Stratified Interpretation (Optional)

For higher precision, interpret spread relative to pair difficulty:

| Pair Difficulty | Average Spread | Adjustment |
|-----------------|----------------|------------|
| Easy (A-T < 0.73) | 63.75 | +0.7 |
| Medium (A-T 0.73–0.78) | 64.84 | — |
| Hard (A-T > 0.78) | 67.55 | -2.7 |

Or simply report percentile vs Haiku on the same pair, which naturally controls for difficulty.

## 6. Score Normalization

### 6.1 When to Use Bootstrap Normalization

| Context | Bootstrap? | Reason |
|---------|------------|--------|
| Cross-pair aggregation | Yes | Controls for pair difficulty |
| Single submission interpretation | Optional | Haiku comparison may suffice |
| Within-pair comparison (human vs Haiku) | No | Same pair, direct comparison |
| Calibration/research | No | Raw distributions needed |

### 6.2 Bootstrap Null Distributions

For contexts requiring normalization, sample random word sets to establish baselines:

1. Sample $n$ random words (matching submission size) without replacement
2. Score this random set using same spread function
3. Repeat 500+ times to build distribution
4. Store mean, std, and raw samples for percentile calculation

### 6.3 Percentile Normalization

Convert raw scores to percentiles against null distribution:

$$
\text{percentile} = 100 \times \frac{|\{s \in S_{\text{null}} : \text{raw} > s\}|}{|S_{\text{null}}|}
$$

### 6.4 Haiku-Relative Scoring

An alternative to bootstrap normalization: compare participant spread to Haiku spread on the same pair.

$$
\Delta_{\text{spread}} = \text{spread}_{\text{participant}} - \text{spread}_{\text{Haiku}}
$$

| Delta | Interpretation |
|-------|----------------|
| < -5 | Well below Haiku baseline |
| -5 to 0 | Slightly below Haiku |
| 0 to +5 | At or above Haiku |
| > +5 | Substantially exceeds Haiku |

This approach naturally controls for pair difficulty without requiring bootstrap sampling.

## 7. Comparison Functions

### 7.1 Participant vs. Haiku Baseline

The primary comparison for INS-001.2:

$$
\Delta_{\text{spread}} = \text{spread}_{\text{participant}} - \text{spread}_{\text{Haiku}}
$$

Interpretation:
- Positive delta: Participant found more divergent bridges than AI
- Negative delta: AI found more divergent bridges
- Near zero: Comparable performance

### 7.2 Validity Check

Before comparing spread, verify both submissions pass relevance threshold:

```python
def compare_to_baseline(participant_result, haiku_result):
    if participant_result["relevance"] < 0.15:
        return {"valid": False, "reason": "participant_invalid"}
    if haiku_result["relevance"] < 0.15:
        return {"valid": False, "reason": "baseline_invalid"}
    
    delta = participant_result["spread"] - haiku_result["spread"]
    return {"valid": True, "delta_spread": delta}
```

## 8. Implementation

### 8.1 Core Functions

The scoring module (`scoring.py`) implements:

| Function | Purpose |
|----------|---------|
| `cosine_similarity()` | Fundamental similarity calculation |
| `calculate_divergence()` | Mean pairwise distance (clue-only for spread) |
| `score_union()` | INS-001.2 complete scoring (relevance + spread) |
| `bootstrap_null_distribution()` | Generate prompt-specific baselines |
| `normalize_scores()` | Convert raw to percentile/z-score |

### 8.2 Return Schema

`score_union()` returns:

```python
{
    "relevance": float,            # Overall relevance (0-1)
    "relevance_individual": list,  # Per-clue relevance scores
    "spread": float,               # Clue-only divergence (0-100)
    "valid": bool                  # Whether relevance >= 0.15
}
```

### 8.3 Embedding Model

Scores depend on the embedding model:

- **Model**: OpenAI text-embedding-3-small (1536 dimensions)
- **Normalization**: L2-normalized vectors
- **Calibration reference**: Claude Haiku 4.5 (claude-haiku-4-5-20251001)

## 9. Limitations

| Limitation | Impact | Mitigation |
|------------|--------|------------|
| **Construct difference from DAT** | Spread ≠ unconstrained divergence | Do not report DAT-equivalent scores; use INS-001.2-specific norms |
| **Relevance-spread tradeoff** | Cannot maximize both simultaneously | Use relevance as validity gate only |
| **Pair difficulty effects** | Harder pairs affect both metrics | Use Haiku-relative comparison or pair-stratified thresholds |
| **Embedding model dependence** | Different models yield different scores | Standardize on single model; document in methods |
| **Haiku baseline stability** | AI capabilities may shift over time | Lock model version; re-calibrate periodically |
| **Cultural bias** | Embeddings encode Western/English associations | Note reference population; limit generalization claims |
